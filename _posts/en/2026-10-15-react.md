**React** is an open source JavaScript library, created by Meta (Facebook), for building user interfaces. It isn't a full framework: it only handles the "view", meaning what appears on screen and how it updates. Routing, data handling and server rendering come from other tools, or from frameworks built on top of React such as Next.js.

### How it works

- **Components**: the interface is built from reusable building blocks (the product card, the "add to cart" button, the menu). Each block is written once and used everywhere, so the interface stays consistent and changes happen in one place.
- **Instant updates**: when something changes (a filter, the cart quantity, a form field) React updates only the affected part of the page, without reloading it. For users the experience feels smooth, like an app.
- **One foundation for web and mobile**: with React Native the same skills also cover iOS and Android apps.
- **On the server or in the browser**: used with a framework like Next.js, React can generate pages on the server, so they arrive complete and readable by Google.

### Typical use cases

- **Interactive web applications**: dashboards, back-office tools, editors, internal tools.
- **Ecommerce**: product configurators, cart drawers, instant filters, custom checkouts, even inside a Shopify theme or a WordPress site.
- **Headless frontends**: with Next.js or Hydrogen on top of Shopify, Contentful or Strapi.
- **Mobile apps** with **React Native**, sharing skills and some logic with the web.
- **Design systems**: component libraries shared across products and teams.
- **Widgets** embedded in existing pages (a calculator, a complex form, a map).

### Advantages

- **A huge ecosystem**: libraries for forms, animation, charts, tables, accessibility, testing.
- **The job market**: it's the most widely used frontend library, so developers and documentation are easy to find.
- **Reusable components** and organised code, even in large projects.
- **A simple mental model**: UI = a function of state.
- **Flexibility**: use it for a small widget or an entire application, on web or mobile.
- **Long-term support**: used in production by Meta and thousands of companies.

### Disadvantages

- **View only**: routing, data and build tooling must be chosen separately. Freedom of choice also means decision fatigue.
- **JavaScript in the browser**: a pure client-side React app ships a lot of JavaScript, slowing the first load and potentially hurting SEO. Public sites need server rendering (Next.js) or an islands approach (Astro).
- **Experience matters**: a badly written React app becomes slow and hard to maintain. Quality depends heavily on who builds it.
- **Fast evolution**: recommended practices change (classes → hooks → Server Components), and old code needs updating.
- **State management** gets complex in large apps: extra libraries are often needed (Zustand, Redux, TanStack Query).

### Comparison with alternatives

| | React | Vue | Svelte | Angular | Vanilla JS / Alpine.js |
| --- | --- | --- | --- | --- | --- |
| Type | UI library | Progressive framework | Compiler / framework | Full framework | No framework / micro-library |
| Learning curve | Medium | Low | Low | High | Very low |
| Browser weight | Medium | Medium | Low | High | Minimal |
| Ecosystem | The largest | Large | Growing | Large, enterprise | Limited |
| Full-stack framework | Next.js, Remix | Nuxt | SvelteKit | Angular itself | — |
| Best for | Almost anything, large teams | Small and mid-size teams | Performance and simplicity | Large enterprise apps | Small interactions |

- **React vs Vue**: Vue's templates are closer to HTML and it's easier at first; React has a bigger ecosystem and job market.
- **React vs Svelte**: Svelte compiles components into optimised JavaScript, with less code and less weight; React has more libraries and more available developers.
- **React vs Angular**: Angular is a complete, opinionated framework (routing, forms, HTTP included), suited to large enterprise teams; React is lighter and more flexible.
- **React vs no framework**: for a few interactions on a content site (a menu, an accordion), plain JavaScript or Alpine.js are enough and weigh far less. On Shopify, modern themes use exactly that: Web Components and native JavaScript.

### When to choose it (and when not)

**Yes**, when the interface is rich in state and interaction, when the project will grow and several developers will work on it, or when you want to share skills between web and mobile.

**No**, or not on its own, for a content site (blog, company website) where the first load matters: Astro, a static generator, or React inside Next.js with server rendering are better there. And for a few interactions on an existing page, native JavaScript is often the lightest choice.
