**Astro** is an open source framework for content-driven websites: blogs, company sites, landing pages, documentation, portfolios. Its key feature: by default it ships **zero JavaScript** to the browser, only HTML and CSS. JavaScript is added only where it's actually needed, component by component.

### How it works

- **HTML first**: pages are generated in advance as plain HTML and CSS, the lightest and fastest format a browser can receive, and the easiest for Google to read.
- **Islands of interactivity**: the page is static, and only some interactive elements (the "islands": a carousel, a form, a configurator) load JavaScript. Each one activates only when needed, for example when the user scrolls to it.
- **Reuse what exists**: it can use components written in React, Vue or Svelte, so existing work isn't thrown away.
- **Content from anywhere**: text written in simple files or pulled from a CMS (WordPress, Strapi, Contentful), so editors keep using the tool they know.
- **Static or dynamic**: by default it produces a static site that can be hosted anywhere for almost nothing; if needed, some pages can be generated on every visit.
- **Smooth transitions** between pages, with an app-like feel.

### Typical use cases

- **Blogs and magazines**, with content in Markdown or from a headless CMS (Strapi, Contentful, WordPress).
- **Company sites and landing pages** where load speed affects SEO and conversions.
- **Technical documentation**, with **Starlight**, the official docs theme.
- **Portfolios and personal sites**.
- **Editorial content next to an ecommerce store**: guides, lookbooks or a fast blog linking to Shopify products (via the Storefront API).
- **Progressive migration**: reusing existing React or Vue components inside a much lighter site.

### Advantages

- **Excellent performance** by default: little or no JavaScript, great Core Web Vitals without special effort.
- **Simplicity**: less technology to manage means faster development and cheaper maintenance.
- **Framework freedom**: use the components your team already knows.
- **Great for SEO**: complete HTML, generated ahead of time.
- **Cheap hosting**: a static site runs on any CDN, often for free (GitHub Pages, Netlify, Cloudflare Pages).
- **Official integrations** for sitemaps, MDX, images, Tailwind and the main CMSs.

### Disadvantages

- **Not ideal for highly interactive apps**: with lots of state shared across pages and components, islands get awkward; Next.js or a single-page app fits better.
- **Communication between islands**: islands from different frameworks don't share state natively; you need solutions like *nanostores*.
- **A younger ecosystem** than Next.js: fewer examples and ready-made solutions for complex cases.
- **Long builds** with tens of thousands of static pages, unless you use server rendering.
- **Updated content needs a new build** in static mode (solved with CMS webhooks or server rendering).

### Comparison with alternatives

| | Astro | Next.js | Gatsby | Eleventy (11ty) | Hugo | Jekyll |
| --- | --- | --- | --- | --- | --- | --- |
| Language | JavaScript / TypeScript | JavaScript / TypeScript (React) | JavaScript (React) | JavaScript | Go | Ruby |
| Browser JS | Minimal, islands | Medium | High | None by default | None by default | None by default |
| UI components | React, Vue, Svelte… | React | React | Templates (Nunjucks, Liquid…) | Go templates | Liquid |
| Server rendering | Yes, optional | Yes | Limited | No | No | No |
| Build speed | Good | Good | Slow | Very good | Extremely fast | Average |
| Best for | Modern content sites | Dynamic apps and sites | Existing projects | Simple static sites | Huge sites | Blogs on GitHub Pages |

- **Astro vs Next.js**: Astro ships far less JavaScript and is simpler for content; Next.js fits better when the site is really an application.
- **Astro vs Gatsby**: Gatsby was the reference for static React sites, but it's barely developed today; many Gatsby projects are migrating to Astro.
- **Astro vs Eleventy / Hugo / Jekyll**: the classic generators are more minimal, and Hugo is extremely fast with thousands of pages; Astro adds modern components, interactive islands and server rendering when you need them.

### When to choose it (and when not)

**Yes**, when the site is mostly content (blog, marketing, documentation), when speed and SEO matter, and when you want to reuse React or Vue components without the weight of a single-page app.

**No**, for highly interactive apps with lots of shared state (dashboards, back-office tools, editors), where Next.js or a classic React app fits better, or for a standard Shopify store, where a Liquid theme remains the simplest choice.
