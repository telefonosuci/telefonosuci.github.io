**Next.js** is an open source framework built on React, developed by Vercel. React handles components; Next.js adds everything a complete site or app needs: routing, server rendering, static generation, image and font optimisation, APIs and caching. It's now the most common way to run React in production.

### How it works

- **Pages prepared on the server**: instead of sending the browser an empty page to fill in, Next.js prepares it in advance. Users see it immediately and Google reads all of it.
- **The right rendering for each page**, even within one site:
  - **static** pages, generated once and served very fast from a worldwide network of servers (CDN), ideal for landing pages and articles;
  - **dynamic** pages, generated on every visit, for personalised content such as a customer area;
  - **static pages that refresh themselves** when the data changes, for example a product's price or availability.
- **Interactivity only where needed**: interactive parts (cart, filters, forms) work like an app; the rest is plain HTML, light to load.
- **Frontend and backend together**: forms, APIs and connections to external systems live in the same project.
- **Automatic optimisations**: images resized and converted to lighter formats, fonts loaded without the page "jumping", links preloaded before the click.

### Typical use cases

- **Headless ecommerce**: a custom frontend for Shopify (Storefront API), commercetools or BigCommerce, with static product pages refreshed when price or availability changes.
- **Corporate and marketing sites** with content from Contentful, Strapi, Sanity or headless WordPress.
- **SaaS and dashboards**: an SEO-optimised public area and an interactive logged-in area in the same project.
- **Multilingual, multi-country sites**, with middleware choosing language and market.
- **Content portals** with thousands of pages that need speed and good indexing.
- **Full-stack prototypes**: frontend, APIs and database access in one repository.

### Advantages

- **SEO and performance**: pages arrive as HTML, with good Core Web Vitals when the project is done well.
- **Flexible rendering**: static, dynamic and incremental, chosen page by page.
- **Full-stack in one project**: UI, APIs, forms and server logic together.
- **The whole React ecosystem** at your disposal.
- **Developer experience**: fast hot reload, built-in TypeScript, clear conventions.
- **Easy deployment**: one command on Vercel, but it also runs on Node.js, Docker and other providers (Netlify, Cloudflare, AWS).

### Disadvantages

- **Growing complexity**: Server and Client Components, multi-layer caching and rendering strategies take time to understand properly. Many bugs come from data being cached when it shouldn't be (or vice versa).
- **Frequent changes**: the move from the Pages Router to the App Router, and caching behaviour changing between versions, have required migrations.[^next15]
- **Ties to Vercel**: some features are simpler or better optimised on their platform; elsewhere they need more configuration.
- **Hosting costs**: with lots of dynamic traffic, serverless platforms can get expensive.
- **Overkill** for simple, mostly static sites.

### Comparison with alternatives

| | Next.js | Astro | Remix / React Router | Nuxt | Hydrogen | SvelteKit |
| --- | --- | --- | --- | --- | --- | --- |
| Based on | React | Framework-agnostic (React, Vue, Svelte…) | React | Vue | React (React Router) | Svelte |
| Strength | Versatility, ecosystem | Content sites, zero JS by default | Web standards, forms and data | Next.js equivalent for Vue | Shopify ecommerce | Lightness |
| Browser JavaScript | Medium | Minimal | Medium | Medium | Medium | Low |
| Best for | Dynamic apps and sites | Blogs, marketing, docs | Form-heavy apps | Vue teams | Headless Shopify stores | Teams that want simplicity |

- **Next.js vs Astro**: for a mostly content site, Astro is simpler and ships less JavaScript. Next.js wins when there's lots of interaction, logged-in areas or complex server logic.
- **Next.js vs Hydrogen**: Hydrogen is built by Shopify specifically for Shopify, with ready-made components and tools for cart, products and analytics, plus free hosting on Oxygen. Next.js is more general and lets you combine several data sources and platforms.
- **Next.js vs Remix / React Router**: Remix (now merged into React Router)[^remix] leans on web standards (forms, HTTP requests) and is more predictable; Next.js has more features and a larger ecosystem.
- **Next.js vs Nuxt**: they're equivalents in their respective worlds; the choice depends on whether the team prefers React or Vue.

### When to choose it (and when not)

**Yes**, for headless ecommerce, a site with many dynamic pages, a SaaS with public and logged-in areas, or when you want one project that combines the frontend and a light backend.

**No**, for a simple blog or content site (Astro or a static generator are lighter), for a standard Shopify store (a good Liquid theme is cheaper to maintain and keeps marketing self-sufficient), or if the team has no React experience.

[^next15]: Vercel, [Next.js 15](https://nextjs.org/blog/next-15): `fetch`, `GET` route handlers and the client router cache are no longer cached by default.
[^remix]: Remix, [Merging Remix and React Router](https://remix.run/blog/merging-remix-and-react-router).
