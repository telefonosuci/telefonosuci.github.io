**Strapi** is an open source *headless* CMS written in Node.js (TypeScript). "Headless" means it only manages content and exposes it through APIs: the site, app or screen that displays it is a separate project, built with whatever technology you prefer. Strapi runs on your own server or cloud; alternatively there's **Strapi Cloud**, the managed service.

### How it works

- **Content-Type Builder**: in the admin you define content types (for example *Article* with title, body, image, author) without writing code. Strapi generates the schema files in the project, so the data model is versioned in Git.
- **Collection types and single types**: the former are lists (articles, products), the latter one-off content (the homepage, site settings).
- **Components and Dynamic Zones**: reusable blocks that editors combine to build flexible pages.
- **Automatic APIs**: for each type Strapi creates **REST** endpoints (and **GraphQL** with the dedicated plugin) with filtering, sorting, pagination and relations.
- **Permissions and roles**: you decide who can read or write what, both in the admin and in the APIs (tokens, authenticated users).
- **Extensibility**: controllers, services, middleware, lifecycle hooks and plugins in JavaScript/TypeScript.
- **Database**: PostgreSQL, MySQL/MariaDB or SQLite (handy in development).

### Typical use cases

- **Backend for Next.js, Astro or Nuxt sites**: editors manage content, the frontend reads it at build time or on each request.
- **Multichannel content**: the same article published on the website, mobile app and newsletter.
- **Composable landing pages**: with Dynamic Zones, marketing builds new pages by assembling blocks.
- **Editorial content next to Shopify**: lookbooks, guides and brand stories, while products stay in Shopify.
- **Backend for apps and prototypes**: with users, roles and ready-made APIs, Strapi can act as a light backend for apps that aren't just "content".
- **Projects with data constraints**: when data must stay on European or on-premise servers.

### Advantages

- **Open source and self-hosted**: no pricing per record or per user, full control over data and infrastructure.
- **A flexible data model**, versioned in code.
- **APIs ready immediately**, REST and GraphQL, with filters and relations.
- **A JavaScript stack**: the same language as the frontend, easy for a web team to extend.
- **A clean admin panel**, customisable, with internationalisation, drafts and publishing.
- **A large community** and a plugin marketplace.

### Disadvantages

- **Infrastructure is on you**: servers, database, backups, updates, security and scaling (unless you use Strapi Cloud).
- **Major-version upgrades** take effort: moving from one major to the next (for example v4 to v5) can require code and data migrations.
- **Enterprise features are paid**: some advanced features (such as SSO, review workflows or audit logs) are in paid plans.
- **Fewer editorial tools** than the most mature SaaS CMSs: previews, real-time collaboration and media management need more setup.
- **Performance needs care**: with deep relations, queries can get heavy; careful development and good caching are needed.

### Comparison with alternatives

| | Strapi | Contentful | Sanity | Directus | Payload | Headless WordPress |
| --- | --- | --- | --- | --- | --- | --- |
| Model | Open source, self-hosted or cloud | SaaS | SaaS (open source studio) | Open source, self-hosted or cloud | Open source, self-hosted | Open source, self-hosted |
| Data model | Built in the admin, saved in code | Built in the web app | In code | On an existing database | In code (TypeScript) | Post types and fields |
| APIs | REST, GraphQL | REST, GraphQL | GROQ, GraphQL | REST, GraphQL | REST, GraphQL, Local API | REST (GraphQL via plugin) |
| Cost | Free + hosting | Usage-based plans | Usage-based plans | Free + hosting | Free + hosting | Free + hosting |
| Best for | JS teams that want control | Enterprises and large teams | Publishing and highly structured content | Existing SQL data | Next.js apps | Editors who know WP |

- **Strapi vs Contentful**: Contentful is managed and scales effortlessly, but costs grow with usage and the data model only lives on their platform. Strapi is free and yours, but so is the operational work.
- **Strapi vs Directus**: Directus sits on top of an existing SQL database and turns it into APIs and an admin; Strapi starts from scratch with its own model. Directus shines with existing data, Strapi with new projects.
- **Strapi vs Payload**: Payload is defined entirely in TypeScript and embeds directly into a Next.js app; Strapi is more "ready to use" from the admin.

### When to choose it (and when not)

**Yes**, when you need a flexible headless CMS, your team works in JavaScript, you want control over the data or have constraints on where it's hosted, and you don't want costs that grow with usage.

**No**, if nobody on the team can run servers and updates (a SaaS like Contentful or Sanity, or Strapi Cloud, is better), or if you need an advanced editorial experience out of the box, with visual previews and real-time collaboration.
