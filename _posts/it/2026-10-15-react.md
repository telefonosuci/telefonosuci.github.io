**React** è una libreria JavaScript open source, creata da Meta (Facebook)[^react], per costruire interfacce utente. Non è un framework completo: si occupa solo della "vista", cioè di cosa appare sullo schermo e di come si aggiorna. Routing, gestione dei dati e rendering sul server li aggiungono altri strumenti o framework costruiti sopra React, come Next.js.

### Come funziona

- **Componenti**: l'interfaccia è costruita con mattoncini riutilizzabili (la scheda prodotto, il pulsante "aggiungi al carrello", il menu). Ogni mattoncino si scrive una volta e si usa ovunque, quindi l'interfaccia resta coerente e le modifiche si fanno in un punto solo.
- **Aggiornamenti istantanei**: quando qualcosa cambia (un filtro, la quantità nel carrello, un campo di un form) React aggiorna solo la parte di pagina interessata, senza ricaricarla. Per l'utente l'esperienza è fluida, simile a quella di un'app.
- **Un'unica base per web e mobile**: con React Native le stesse competenze servono anche per le app iOS e Android.
- **Sul server o nel browser**: usato con un framework come Next.js, React può generare le pagine sul server, così arrivano subito complete e leggibili da Google.

### Casi d'uso tipici

- **Applicazioni web interattive**: dashboard, gestionali, editor, strumenti interni.
- **Ecommerce**: configuratori di prodotto, carrelli laterali, filtri istantanei, checkout personalizzati, anche dentro un tema Shopify o un sito WordPress.
- **Frontend headless**: con Next.js o Hydrogen sopra Shopify, Contentful o Strapi.
- **App mobile** con **React Native**, condividendo competenze e parte della logica con il web.
- **Design system**: librerie di componenti condivise tra più prodotti e team.
- **Widget** da inserire in pagine esistenti (un calcolatore, un form complesso, una mappa).

### Vantaggi

- **Ecosistema enorme**: librerie per form, animazioni, grafici, tabelle, accessibilità, test.
- **Mercato del lavoro**: è la libreria frontend più diffusa, quindi è facile trovare sviluppatori e documentazione.
- **Componenti riutilizzabili** e codice organizzato anche su progetti grandi.
- **Modello mentale semplice**: interfaccia = funzione dello stato.
- **Flessibilità**: si usa per un piccolo widget o per un'intera applicazione, sul web o su mobile.
- **Supporto a lungo termine**: usato in produzione da Meta e da migliaia di aziende.

### Svantaggi

- **Solo la vista**: routing, dati e build vanno scelti a parte. La libertà di scelta diventa anche fatica decisionale.
- **JavaScript nel browser**: un'app React pura (client-side) manda molto JavaScript, che rallenta il primo caricamento e può penalizzare la SEO. Per i siti pubblici serve rendering sul server (Next.js) o un approccio a isole (Astro).
- **Serve esperienza**: un'app React scritta male diventa lenta e difficile da mantenere. La qualità dipende molto da chi la sviluppa.
- **Evoluzione rapida**: le pratiche consigliate cambiano (classi → hook → Server Components)[^react19], e il codice vecchio va aggiornato.
- **Gestione dello stato** complessa nelle app grandi: spesso servono librerie aggiuntive (Zustand, Redux, TanStack Query).

### Confronto con le alternative

| | React | Vue | Svelte | Angular | JS "vanilla" / Alpine.js |
| --- | --- | --- | --- | --- | --- |
| Tipo | Libreria per la UI | Framework progressivo | Compilatore / framework | Framework completo | Nessun framework / micro-libreria |
| Curva di apprendimento | Media | Bassa | Bassa | Alta | Molto bassa |
| Peso nel browser | Medio | Medio | Basso | Alto | Minimo |
| Ecosistema | Il più ampio | Ampio | In crescita | Ampio, enterprise | Limitato |
| Framework "full-stack" | Next.js, Remix | Nuxt | SvelteKit | Angular stesso | — |
| Ideale per | Quasi tutto, team grandi | Team piccoli e medi | Prestazioni e semplicità | Grandi app aziendali | Piccole interazioni |

- **React vs Vue**: Vue ha template più vicini all'HTML ed è più facile all'inizio; React ha un ecosistema e un mercato più grandi.
- **React vs Svelte**: Svelte compila i componenti in JavaScript ottimizzato, con meno codice e meno peso; React ha più librerie e più sviluppatori disponibili.
- **React vs Angular**: Angular è un framework completo e "opinato" (routing, form, HTTP inclusi), adatto a grandi team aziendali; React è più leggero e flessibile.
- **React vs niente framework**: per qualche interazione su un sito di contenuti (un menu, un accordion), JavaScript puro o Alpine.js bastano e pesano molto meno. Su Shopify, i temi moderni usano proprio Web Components e JavaScript nativo.

### Quando sceglierlo (e quando no)

**Sì**, quando l'interfaccia è ricca di stato e interazioni, quando il progetto crescerà e lavoreranno più sviluppatori, o quando vuoi condividere competenze tra web e mobile.

**No**, o non da solo, per un sito di contenuti (blog, sito aziendale) dove conta il primo caricamento: lì è meglio Astro, un generatore statico, o React dentro Next.js con rendering sul server. E per poche interazioni su una pagina esistente, JavaScript nativo è spesso la scelta più leggera.
