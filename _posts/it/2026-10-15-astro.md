**Astro** è un framework open source per siti orientati ai contenuti: blog, siti aziendali, landing page, documentazione, portfolio. La sua caratteristica principale: di default manda al browser **zero JavaScript**, solo HTML e CSS.[^islands] Il JavaScript si aggiunge solo dove serve davvero, componente per componente.

### Come funziona

- **HTML prima di tutto**: le pagine vengono generate in anticipo come semplice HTML e CSS, il formato più leggero e veloce che un browser possa ricevere, e il più facile da leggere per Google.
- **Isole di interattività**: la pagina è statica, e solo alcuni elementi interattivi (le "isole": un carosello, un form, un configuratore) caricano JavaScript. Ognuna si attiva solo quando serve, ad esempio quando l'utente ci arriva scorrendo.
- **Riusa quello che esiste**: può usare componenti scritti in React, Vue o Svelte, quindi non si butta il lavoro già fatto.
- **Contenuti da dove vuoi**: testi scritti in file semplici oppure presi da un CMS (WordPress, Strapi, Contentful), così i redattori continuano a usare lo strumento che conoscono.
- **Statico o dinamico**: di default produce un sito statico, ospitabile ovunque a costo quasi nullo; se serve, alcune pagine possono essere generate a ogni visita.
- **Transizioni fluide** tra una pagina e l'altra, con un effetto simile a un'app.

### Casi d'uso tipici

- **Blog e magazine**, con contenuti in Markdown o da un CMS headless (Strapi, Contentful, WordPress).
- **Siti aziendali e landing page** dove la velocità di caricamento incide su SEO e conversioni.
- **Documentazione tecnica**, con **Starlight**, il tema ufficiale per la documentazione.[^starlight]
- **Portfolio e siti personali**.
- **Contenuti editoriali accanto a un ecommerce**: guide, lookbook o un blog veloce che rimanda ai prodotti di Shopify (via Storefront API).
- **Migrazione progressiva**: riutilizzare componenti React o Vue esistenti dentro un sito molto più leggero.

### Vantaggi

- **Prestazioni eccellenti** di default: poco o nessun JavaScript, ottimi Core Web Vitals senza sforzi particolari.
- **Semplicità**: meno tecnologia da gestire significa sviluppo più rapido e manutenzione più economica.
- **Libertà di framework**: si usano i componenti che il team già conosce.
- **Ottimo per la SEO**: HTML completo, generato in anticipo.
- **Hosting economico**: un sito statico si ospita su qualsiasi CDN, spesso gratis (GitHub Pages, Netlify, Cloudflare Pages).
- **Integrazioni ufficiali** per sitemap, MDX, immagini, Tailwind, e i principali CMS.

### Svantaggi

- **Non ideale per app molto interattive**: con molto stato condiviso tra pagine e componenti, le isole diventano scomode; Next.js o una single-page app sono più adatti.
- **Comunicazione tra isole**: isole di framework diversi non condividono lo stato in modo nativo; servono soluzioni come *nanostores*.
- **Ecosistema più giovane** di Next.js: meno esempi e soluzioni pronte per casi complessi.
- **Build lunghe** con decine di migliaia di pagine statiche, se non si usa il rendering sul server.
- **Il contenuto aggiornato richiede una nuova build** in modalità statica (risolvibile con webhook dal CMS o rendering sul server).

### Confronto con le alternative

| | Astro | Next.js | Gatsby | Eleventy (11ty) | Hugo | Jekyll |
| --- | --- | --- | --- | --- | --- | --- |
| Linguaggio | JavaScript / TypeScript | JavaScript / TypeScript (React) | JavaScript (React) | JavaScript | Go | Ruby |
| JS nel browser | Minimo, a isole | Medio | Alto | Nessuno di default | Nessuno di default | Nessuno di default |
| Componenti UI | React, Vue, Svelte… | React | React | Template (Nunjucks, Liquid…) | Template Go | Liquid |
| Rendering sul server | Sì, opzionale | Sì | Limitato | No | No | No |
| Velocità di build | Buona | Buona | Lenta | Molto buona | Velocissima | Media |
| Ideale per | Siti di contenuti moderni | App e siti dinamici | Progetti esistenti | Siti statici semplici | Siti enormi | Blog su GitHub Pages |

- **Astro vs Next.js**: Astro manda molto meno JavaScript ed è più semplice per i contenuti; Next.js è più adatto quando il sito è in realtà un'applicazione.
- **Astro vs Gatsby**: Gatsby è stato il riferimento per i siti statici in React, ma oggi è poco sviluppato; molti progetti Gatsby migrano proprio ad Astro.
- **Astro vs Eleventy / Hugo / Jekyll**: i generatori classici sono più minimali e Hugo è velocissimo con migliaia di pagine; Astro aggiunge componenti moderni, isole interattive e rendering sul server quando servono.

### Quando sceglierlo (e quando no)

**Sì**, quando il sito è soprattutto contenuto (blog, marketing, documentazione), quando contano velocità e SEO, e quando vuoi riutilizzare componenti React o Vue senza il peso di una single-page app.

**No**, per applicazioni molto interattive con tanto stato condiviso (dashboard, gestionali, editor), dove Next.js o un'app React classica sono più adatti, o per un negozio Shopify standard, dove un tema Liquid resta la scelta più semplice.
